# Ring-array frequency-domain FWI

`invert_ring_fdfd.py` estimates a spatially varying sound-speed map from
steady-state complex pressure data.  It uses the same 200 mm square field of
view and 70 mm ring geometry as `../invert_ring.py`, but solves the
constant-density Helmholtz equation with finite differences instead of running
an FDTD time history.

The forward and adjoint equations are matrix-free CUDA tensor operations.
Independent transmitter systems are batched, which makes an NVIDIA GPU such as
an A6000 the intended execution platform.  The default 161 x 161 grid is
purposefully lower resolution than the 401 x 401 time-domain example: direct
frequency-domain solves become expensive rapidly as the grid is refined.

## Run

From the repository root:

```bash
python fdfd_ring/invert_ring_fdfd.py --device cuda --allow-tf32 --no-show
```

For a GPU-resident quasi-Newton reconstruction, use projected L-BFGS:

```bash
python fdfd_ring/invert_ring_fdfd.py --device cuda --optimizer lbfgs \
  --lbfgs-history-size 10 --lbfgs-max-eval 8 --no-show
```

PyTorch does not provide a literal L-BFGS-B optimizer.  This option uses
`torch.optim.LBFGS` with its strong-Wolfe line search, then projects every
accepted update into the speed limits set by `--c-min` and `--c-max`.  Its
history vectors and objective evaluations remain on the selected GPU.

Useful first changes are:

```bash
# Faster smoke reconstruction
python fdfd_ring/invert_ring_fdfd.py --device cuda --grid-size 81 \
  --n-elements 32 --n-shots 8 --shot-batch 8 --frequencies-khz 50,75 \
  --max-iter 5 --no-show

# Validate the complex adjoint sign and conjugation convention
python fdfd_ring/invert_ring_fdfd.py --device cuda --gradient-check

# Use a CT-derived map generated by ct_to_speed.py
python fdfd_ring/invert_ring_fdfd.py --device cuda --ct-speed abdomen_acoustic.npz \
  --frequencies-khz 50,75,100 --no-show
```

The solver uses restarted complex GMRES with a Jacobi preconditioner and a fixed
quadratic imaginary absorbing layer.  If a solve emits a residual warning,
increase `--solver-maxiter`, use fewer/higher-damped frequencies, or increase
`--pml-strength`.  Frequency continuation is done by calling low frequencies
first and then adding higher frequencies to `--frequencies-khz`.

This initial implementation estimates sound speed only; density, attenuation,
source calibration, and measured-data preprocessing are intentionally outside
its scope.

## Standalone forward simulator

`forward_ring_fdfd.py` is the steady-state counterpart to `../2DRingFDTD.py`.
It emits one monochromatic point source and records complex pressure at every
ring receiver:

```bash
python fdfd_ring/forward_ring_fdfd.py --device cuda --frequency-khz 75 \
  --save-data fdfd_pressure.npz --save-figure fdfd_forward.png --no-show
```

Add `--parallel-shots 8` to simulate every ring element as a transmitter in
CUDA batches of eight.  The data archive stores `pressure` with shape
`(n_transmitters, n_receivers)` as `complex64`, plus the medium and geometry.
